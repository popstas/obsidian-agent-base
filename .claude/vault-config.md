# Пути vault для скиллов обзоров

Читают `weekly-review`, `monthly-review` и `weekly-report` (ключи `weekly_report`,
`report_day`, `monthly_report`, `year_goals`). Если файла нет, эти скиллы падают
обратно на Glob по дефолтным путям ядра или на документированный дефолт ключа —
см. их `SKILL.md`. Заполняется/проверяется при адаптации vault, см. `INTEGRATION.md`.

- `weekly_report`: `Log/Reports/????-??-??.md` — недельные отчёты (`weekly-report`);
  basename — дата дня `report_day` отчётной недели (`YYYY-MM-DD.md`), актуальный — с последней датой.
- `report_day`: день недели, которым заканчивается отчётный период (`weekly-report`,
  `weekly-review`), например `воскресенье` или `среда`. Ключа нет — воскресенье.
- `monthly_report`: `Log/Reports/????-??.md` — месячные итоги (`monthly-review`);
  basename — `YYYY-MM.md`, лежат в той же папке, что и недельные, отличаются форматом имени.
- `year_goals`: `Notes/*/Цели *.md` — файл целей года, например `Notes/2026/Цели 2026.md`;
  basename уникален глобально (см. правило wikilink-резолвинга в `obsidian-vault`).

Если ключа/файла для конкретного шага нет — соответствующий шаг обзора пропускается,
это штатное поведение (см. `SKILL.md` weekly-review/monthly-review, раздел «Пути vault»).

- `dashboard`: имя заметки-дашборда vault, если она есть. В ней может лежать готовая строка «7 дней: +N / ✅ M», её использует `weekly-review`. Ключа нет — скилл считает сам.
- `tasks_legend`: строка-легенда под заголовком `# Week+` в `tasks.md`. Скиллы её не удаляют и не переставляют. Ключа нет — не трогай строку, начинающуюся с `> Активные задачи`.
- `work_email`: рабочий ящик для разбора входящих в `weekly-review`. Ключа нет — раздел разбора почты пропускается молча.
