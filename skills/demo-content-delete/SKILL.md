Скилл одноразовый: в конце он удаляет сам себя. Запускается один раз, после того как вольт адаптирован под пользователя.

## Когда останавливаться и спрашивать

Демо-файл мог быть отредактирован пользователем — тогда в нём есть его работа, и удалять молча нельзя. Единственный признак — sha256 из `demo-manifest.json`.

## Порядок

### 1. Прочитать манифест

Прочитай `demo-manifest.json` в корне вольта.

- **Есть** — иди к шагу 2.
- **Нет** — сам по себе этот факт не значит, что демо убрано: так выглядит и прерванный прошлый запуск (шаг 6 удаляет манифест первым делом, ещё до удаления себя), и ручное удаление файла пользователем. Разберись, прежде чем что-то утверждать:
  1. `git show HEAD:demo-manifest.json` — если манифест находится, восстанови его на диск в исходном виде и продолжай с шага 2 как обычно. Скилл ничего не коммитит сам (см. шаг 6), поэтому пока прошлый запуск не закоммичен, манифест почти всегда восстановим так. Если демо-файлы и демо-блоки уже разобраны прошлым запуском, шаги 2–3 просто ничего не найдут — это нормально, не ошибка.
  2. Не нашёлся и в HEAD (удаление закоммичено, либо манифеста никогда не было) — хэши потеряны безвозвратно, отличить нетронутый демо-файл от правки пользователя больше нельзя. Выполни грep из шага 5 — он найдёт явные остатки (демо-блоки, ссылки на две демо-заметки), но не всеобъемлющ: демо-файл без этих меток в тексте (например, отчёт `Log/Reports/...`) он не покажет. Честно предупреди пользователя об этом ограничении, покажи всё, что нашёл грep, и спроси, что с этим делать, — не решай сам.
  3. Если по итогам проверки демо-следов не осталось, а `skills/demo-content-delete/` всё ещё на месте — скилл просто не доудалил себя в прошлый раз: доделай шаг 6. Только когда делать больше нечего вовсе, сообщи, что демо уже было убрано, и останови.

### 2. Разобраться с целыми демо-файлами

Для каждой записи `demoFiles`:

1. Если файла нет — пропусти молча.
2. Посчитай sha256 файла и сравни с `sha256` из манифеста. Кросс-платформенно (Node есть везде, `sha256sum` — нет на Windows):
   ```bash
   node -e "console.log(require('crypto').createHash('sha256').update(require('fs').readFileSync(process.argv[1])).digest('hex'))" "<путь>"
   ```
3. **Совпал** — файл не тронут, удали его.
4. **Разошёлся** — покажи пользователю дифф относительно версии из git (`git show HEAD:"<путь>"`, путь в кавычках — в именах демо-заметок бывают пробелы и кириллица) и спроси: удалить целиком, оставить целиком, или удалить только демо-часть. Без ответа не удаляй.

Собери список удалённого и изменённого — он понадобится в шаге 6.

### 3. Вырезать демо-блоки из живых файлов

Для каждой записи `demoBlocks` файл остаётся, а из него удаляются участки между `<!-- demo:begin -->` и `<!-- demo:end -->` вместе с самими маркерами. У каждой записи `demoBlocks` в манифесте есть свой `sha256` — baseline, снятый со всех размеченных регионов файла (маркеры включены, конкатенация в порядке появления в файле). Он существует именно для того, чтобы отличить нетронутый демо-блок от блока, в который пользователь дописал свою настоящую задачу — это как раз то место, куда `new-task`/`close-task` вставляют новые и закрытые строки.

1. Посчитай хэш той же конкатенации размеченных регионов, тем же способом, что и `scripts/gen-demo-manifest.mjs`:
   ```bash
   node -e '
   const fs = require("fs");
   const text = fs.readFileSync(process.argv[1], "utf8");
   const B = "<!-- demo:begin -->", E = "<!-- demo:end -->";
   let idx = 0, regions = [];
   for (;;) {
     const b = text.indexOf(B, idx);
     if (b === -1) break;
     const e = text.indexOf(E, b);
     if (e === -1) break;
     regions.push(text.slice(b, e + E.length));
     idx = e + E.length;
   }
   console.log(require("crypto").createHash("sha256").update(regions.join("")).digest("hex"));
   ' "<путь>"
   ```
2. Сравни с `sha256` записи `demoBlocks` в манифесте.
3. **Совпал** — блок не тронут, вырежь маркеры и всё между ними молча.
4. **Разошёлся** — покажи пользователю диф размеченных регионов относительно версии из git (`git show HEAD:"<путь>"`) и спроси: вырезать демо-часть и оставить дописанное, оставить всё как есть, или что-то ещё. **Без ответа не вырезай** — точно так же, как в шаге 2 для целых файлов.
5. Если маркеров в файле нет — блоки уже вырезаны, пропусти файл.

Заголовки секций (`# Week:`, `# Week+`), строки-легенды и структуру файла **не трогай** в любом случае — при совпадении хэша удаляется только содержимое блоков между маркерами.

После правки `tasks.md` перегенерируй счётчик: `node .claude/gen-tasks-json.cjs`.

### 4. Предложить удалить файлы, нужные только базе

Отдельным шагом, **с явным подтверждением**: пути из `baseOnly` нужны для разработки самой базы и бесполезны в личном вольте — тесты, CI, git-хуки, конфиг changelog, спеки и планы.

Каждая запись `baseOnly` — это либо файл (`CONTRIBUTING.md`, `cliff.toml`), либо каталог (`tests`, `.githooks`, `.github`, `docs/superpowers`); список их не различает. Определяй тип на месте: каталог удаляй рекурсивно, файл — как файл. Если пути нет вовсе — пропусти молча, это не ошибка (например, `CONTRIBUTING.md` в некоторых версиях базы ещё не появился).

Спроси прямо: «Планируешь присылать улучшения обратно в obsidian-agent-base?»

- **Да** — оставь всё, просто сообщи, что оставил.
- **Нет** — удали пути из `baseOnly`, а также `package.json` и `CHANGELOG.md`, если пользователь не против потерять `npm test`.

Не удаляй `scripts/` целиком: `install-obsidian-plugins.mjs` и `gen-skills-list.mjs` полезны и в личном вольте.

### 5. Проверить, что демо не осталось в ссылках

```bash
grep -rn "Обустройство вольта\|Созвон по вольту\|demo:begin" --include="*.md" --exclude-dir=demo-content-delete .
```

`--exclude-dir=demo-content-delete` исключает сам этот `SKILL.md` — он неизбежно упоминает эти строки в собственном тексте (маркеры, названия демо-заметок, эта же грep-команда), и это не следы забытого демо, а инструкция, которая тебе ещё нужна до шага 6. Совпадения внутри путей из `baseOnly` (например, `docs/superpowers`) тоже не в счёт — их судьбу ты уже решил в шаге 4, будь то удаление или осознанное сохранение как дев-документации базы. Всё остальное найденное — недоделанная работа: либо остались блоки, либо на удалённые заметки ссылаются другие файлы вольта. Битые wikilinks исправь или убери.

### 6. Удалить себя и манифест

Последним действием, и обязательно в этом порядке — манифест первым, каталог скилла вторым. Так прерывание между под-шагами остаётся понятным: манифест пропал, а `skills/demo-content-delete/` ещё жив → шаг 1 при следующем запуске это распознает и доделает хвост. Если удалить в обратном порядке, прерывание сразу после удаления каталога скилла лишает возможности запустить его повторно — а манифест и `Skills list.md` так и останутся не приведены в порядок, и починить это можно будет только руками: сам скилл больше не сможет.

1. Удали `demo-manifest.json`.
2. Удали каталог `skills/demo-content-delete/`.
3. Если `scripts/gen-skills-list.mjs` на месте — перегенерируй список: `node scripts/gen-skills-list.mjs`.
4. Покажи пользователю итог: что удалено, что оставлено по его просьбе, что он правил руками.

Не коммить изменения сам — покажи `git status` и предложи закоммитить.
