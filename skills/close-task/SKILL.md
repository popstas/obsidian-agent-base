# close-task

Закрываешь задачу в `tasks.md` и фиксируешь результат в дневном логе. Цель — чтобы список задач и журнал дня всегда сходились.

## Дата

1. Если пользователь указал дату закрытия — используй её.
2. Иначе возьми текущую дату из окружения.
3. Формат даты: `YYYY-MM-DD`.

## Найти задачу

1. Открой `tasks.md` в корне vault.
2. Найди задачу по точному или очевидному частичному совпадению с запросом пользователя.
3. Учитывай только строки задач Markdown:
   - открытые: `- [ ] ...`
   - промежуточные: `- [/] ...`
   - закрытые: `- [x] ...`
4. Если найден ровно один очевидный кандидат — работай с ним.
5. Если найдено несколько похожих кандидатов, не редактируй файлы. Покажи список кандидатов и попроси уточнить.
6. Если задача не найдена, не создавай её автоматически. Скажи, что не нашёл, и предложи сначала добавить задачу или записать факт через `worklog`.

## Закрыть в tasks.md

Для найденной задачи:

1. Если строка начинается с `- [ ]` или `- [/]`, замени чекбокс на `- [x]`.
2. Если в строке ещё нет закрывающей даты `✅ YYYY-MM-DD`, добавь в конец ` ✅ YYYY-MM-DD`.
3. Если задача уже `- [x]` и дата есть — не меняй строку.
4. Если задача уже `- [x]`, но даты нет — добавь ` ✅ YYYY-MM-DD`.
5. Сохрани дату создания `➕ YYYY-MM-DD`, если она есть. Не удаляй ссылки, комментарии после тире, wikilinks и уже записанные уточнения.
6. Если у закрываемой задачи нет `➕ YYYY-MM-DD`, не придумывай дату создания задним числом; добавь только `✅ YYYY-MM-DD`.
7. `tasks.md` разбит на две секции-заголовка: `# Week:` (текущая неделя) и `# Week+` (неделя+). Завершённые задачи собираются в **верхний блок `- [x]` под заголовком `# Week:`** (в начале файла). Перемести закрытую задачу вместе со всеми её подпунктами туда: сразу после заголовка `# Week:` и последней строки верхнего блока `- [x] ...`, перед первой открытой задачей `- [ ] ...`. Задачу, закрытую из секции `# Week+`, тоже переноси в этот верхний блок Week. Если задача уже закрыта, но стоит среди открытых, всё равно перемести её в конец завершённого блока. Заголовки `# Week:` / `# Week+` и строку-легенду `> Активные задачи. Будущие: [[tasks-future]]. Отложенные: [[tasks-snoozed]]. Проекты: [[projects]].` не удаляй и не переставляй.

Пример:

```md
- [ ] Посмотреть отчёты за месяц ➕ 2026-04-29
```

становится:

```md
- [x] Посмотреть отчёты за месяц ➕ 2026-04-29 ✅ 2026-04-29
```

## Снять галочку в projects.md

Ближайшая задача проекта живёт в двух местах: планом в `projects.md` и обычной задачей в `# Week:`. Закрывать нужно оба, иначе проект выглядит застрявшим.

1. Проверь, есть ли у закрытой задачи подпункт-обратная ссылка вида `- Проект: [[projects]] (<название проекта>)`. Если нет — раздел не применяется, переходи к дневному логу.
2. Открой `projects.md`, найди проект по названию из обратной ссылки.
3. Внутри проекта найди подчекбокс с тем же текстом, что у закрытой задачи, и отметь его `- [x]`, добавив ` ✅ YYYY-MM-DD` той же датой. Дату создания `➕`, если она есть, сохрани.
4. Если совпадения по тексту нет — не угадывай и не правь похожий пункт. Покажи пользователю план проекта и спроси, какой пункт закрыть.
5. Если в плане проекта после закрытия остались открытые подчекбоксы — назови следующий и предложи завести его в `# Week:` (это и есть зеркалирование ближайшей задачи). Если открытых не осталось — скажи, что проект можно закрывать целиком.
6. Если `projects.md` в vault нет — раздел не применяется.

## Записать итог в дневной лог

После обновления `tasks.md` добавь итог в `Log/YYYY/MM/YYYY-MM-DD.md` по правилам `worklog`:

1. Если файла нет — создай.
2. Заголовок блока — формулировка закрытой задачи без чекбокса, `➕ YYYY-MM-DD` и `✅ YYYY-MM-DD`.
3. Если блок уже есть — допиши туда итог.
4. Если пользователь дал итог после тире или в отдельном предложении — запиши его как факт.
5. Если пользователь не дал итог — запиши коротко: `- Закрыл задачу.`.
6. Если в задаче есть ссылка или wikilink, сохрани её в дневной записи, если она помогает понять результат.

Минимальный формат:

```md
## <Название закрытой задачи>

- Закрыл задачу: <краткий итог>.
```

Если в итоговом сообщении есть вопросы, риски или следующие шаги, оформи их так же, как в `worklog`:

```md
### Вопросы / риски
- <вопрос или риск>

### Что дальше
- <следующий шаг>
```

Пустые подразделы не выводи.

## Защита от ошибок

- Не закрывай неоднозначную задачу автоматически.
- Не закрывай родительскую задачу, если пользователь явно говорит о подзадаче.
- Не создавай дубль дневного блока, если уже есть такой же заголовок.
- Не дублируй дату закрытия, если она уже записана.
- Не удаляй и не меняй дату создания `➕ YYYY-MM-DD`.
- Не переписывай старые итоги в дневном логе; только добавляй новый факт, если нужно.

## Проверка перед ответом

Перед завершением проверь:

1. В `tasks.md` закрыта ровно одна задача.
2. У закрытой задачи есть `✅ YYYY-MM-DD`.
3. Если у задачи была дата создания `➕ YYYY-MM-DD`, она сохранилась.
4. Закрытая задача стоит в верхнем блоке завершённых задач под заголовком `# Week:`, перед первой открытой задачей.
5. В `Log/YYYY/MM/YYYY-MM-DD.md` есть запись с итогом.
6. Ссылки и wikilinks не потерялись.
7. Если задача была неоднозначной, файлы не изменены.
8. Если у задачи была обратная ссылка на проект, соответствующий подчекбокс в `projects.md` тоже закрыт.

В финальном ответе кратко скажи, какая задача закрыта и куда записан итог.
