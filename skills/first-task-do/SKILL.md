# first-task-do

Тонкая обёртка над `task-prepare`: находит первую открытую задачу и отдаёт её туда. Вся работа - выбор задачи и делегирование; исследование, заметка-разбор и защита от повторного разбора живут в `task-prepare`.

## Выбор задачи

1. Найди `tasks.md` в корне вольта.
2. Закрытой считается только строка `- [x]`. Пустой `- [ ]`, статус стороннего плагина и обычный незачёркнутый буллет - открытые. Правило - в `obsidian-vault` («Закрытость чекбокса»).
3. Бери первую открытую задачу в порядке файла. Приоритет задаёт порядок строк, а не заголовки: не прыгай в `# Week+`, пока выше есть открытая задача.
4. Открытых задач нет - скажи прямо и закончи. Не выдумывай работу.

Быстрая проверка, какая задача выберется:

```bash
./.scripts/task-prepare first --dry-run
```

## Дальше

Вызови `task-prepare` с текстом выбранной задачи и следуй ему целиком - включая шаг 0 (проверка, не разобрана ли задача уже) и три обязательных артефакта. Своих правил про read-only, браузер и формат ответа здесь нет: они там.

Если задача уже подготовлена, `task-prepare` вернёт путь к готовому разбору. Это нормальный исход `/first-task-do`: прочитай разбор и скажи, что по задаче уже известно и чего не хватает для старта.

## Автоматический запуск

Без участия человека то же самое делает CLI:

```bash
./.scripts/task-prepare first
```

Он сам находит первую открытую задачу и запускает `claude -p "/task-prepare <задача>"`, только если её ещё не разбирали. На уже подготовленной задаче не тратит ни одного токена.
